# 실제 Codex 토큰 A/B 측정

2026-10-25, 설치된 Codex CLI `0.164.0-alpha.11.1`의 ChatGPT 구독 로그인으로 추론 4회를 실행했다. API 키는 사용하지 않았고 기존 채팅·전역 설정·모델 기본값을 변경하지 않았다. 아래 수치는 문자 수 추정이 아니라 `codex exec --json`의 `turn.completed.usage`다.

## 방법

- 모델 `gpt-6.1-sol`, 추론 강도 `low`로 통일했다. 현재 채팅의 기록과 같은 설정이다.
- 짧은 로그: 실제 보조 도구 검사 18개의 결과. 긴 로그: 같은 검사를 4번 실행한 실제 72개 검사 결과다. 긴 표본은 반복 검사의 조건이며 일반 개발 작업의 평균을 대표하지 않는다.
- 동일한 원본에서 원문과 `run_logged.summarize` 처리본을 만들었다. 압축본에는 고정된 stdout/stderr 구분·원본 보관 안내를 넣었다. 전체 래퍼의 실제 경로·처리량 footer는 포함하지 않아 전체 실행 비용과는 차이가 있다.
- 같은 지시문으로 로그의 최종 테스트 수·제외 수·성공 여부를 JSON 한 줄로 답하도록 했다. 파일 탐색·수정·도구 호출은 없었다. 프로젝트 지침은 두 조건 모두 동일하므로 AGENTS 경량화나 장기 대화 효과는 이 실험에 포함되지 않는다.
- 짧은 원문 → 짧은 압축 → 긴 압축 → 긴 원문 순서로 각 1회 실행했다. 각 실행은 독립된 새 CLI 세션이다. 도구 결과를 입력으로 받는 실제 개발 루프 전체가 아니라, 제공된 로그를 해석하는 단일 추론 비교다.

## 결과

| 조건 | 원문 입력 토큰 | 압축 입력 토큰 | 입력 감소율 |
| --- | ---: | ---: | ---: |
| 짧은 검사 로그 | 15,602 | 15,615 | -0.08% (13개 증가) |
| 긴 반복 검사 로그 | 22,501 | 15,774 | 29.90% (6,727개 감소) |

네 실행 모두 캐시 입력 12,288개, 출력 18개, 추론 출력 0개였다. 캐시 토큰은 입력 토큰에 포함되므로 합산하지 않는다. 긴 로그의 입력+출력 합계는 22,519 → 15,792개로 29.87% 감소했다. 짧은 로그는 15,620 → 15,633개로 증가했다.

모든 답변은 정확했다. 짧은 로그는 tests=18/skipped=1/ok=true, 긴 로그는 tests=72/skipped=4/ok=true였으며 도구 호출은 모두 0회였다. 실행 시간은 각각 3.724초·4.075초·4.095초·3.773초였다. 단일 표본의 시간 차이로 속도 개선을 주장하지 않는다.

## 구독 사용량의 한계

계정 기록의 5시간·주간 `used_percent`를 전후 확인했지만 작은 실행별 소모량을 분리할 정밀도가 없었다. 계정 전체 사용률과 지연·반올림, 현재 채팅의 작업도 영향을 주므로 **구독 한도 절감률은 산출하지 않았다**. 입력 토큰 29.9% 감소를 구독 사용량 29.9% 절감으로 환산할 수 없다.

[공식 요금·사용 한도 문서](https://learn.chatgpt.com/docs/pricing)는 모델·문맥·추론·도구·검색·캐시 등이 사용량에 영향을 주며 프롬프트 길이만으로 한도를 추정할 수 없다고 설명한다. [CLI JSON 사용량 형식](https://learn.chatgpt.com/docs/non-interactive-mode)도 참고한다.

판단: 긴 성공 로그를 줄이는 효과는 이 표본에서 실제 입력 토큰으로 확인됐다. 짧은 로그에는 이득이 없었으며, 전체 개발·장기 대화·구독 절감률을 일반화할 근거는 아직 없다. 계정 한도를 정밀하게 측정하려고 대량 추론을 추가하지 않았다.

## 재현 자료와 발견 사항

원문·압축본·CLI 이벤트·계정 한도 스냅샷·실행 스크립트는 `.codex-local/token-ab/`에 사용자 전용 로컬 자료로 남겼다. Git에 포함하거나 외부로 전달하지 않는다. 재실행하면 구독 사용량을 소모하므로 자동·정기 실행을 등록하지 않았다.

반복 검사 준비 중 로그 폴더 초기화에서 병렬 실행 경쟁 조건을 발견했다. 초기화 잠금으로 수정 후 실제 반복 검사 72개(Windows 전용 4개 제외)가 통과했다. Windows에서도 18개 중 16개 통과·POSIX 전용 2개 제외를 재확인했다. 잠금이 남아 있으면 10초 후 실행 전에 실패하며 기존 프로세스나 잠금을 강제로 제거하지 않는다.
