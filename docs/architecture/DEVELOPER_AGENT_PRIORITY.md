# 1순위: 지시를 받아 자기 개발 코드를 수정하는 AI

결정일: 2026-10-27. 사용자 요청에 따라 지속 학습 로드맵의 실행 순서를 변경한다.

## 제품 목표

Role-AI 내부의 개발자 모드 AI가 사용자와 직접 대화하고, 필요한 외부 사이트·문서를 읽고,
사용자가 지시한 변경을 **Role-AI 자신의 개발 저장소**에 적용하는 에이전트가 된다.
사용자가 계속 파일 내용을 옮겨주거나 코드를 대신 수정하지 않아도 계획→조사→수정→검증→PR 처리를 이어간다.
지시가 불분명하면 대화로 필요한 내용을 확인하고, 실행 중 진행 상태와 실제 결과를 보여준다.

여기서 자기 수정은 애플리케이션 소스의 개발 브랜치 수정이다. 모델 가중치 학습과 운영 프로세스의 즉시 교체는 별도다.
Codex가 대신 작성한 코드나 프롬프트에 경로를 적어둔 것만으로 Role-AI 자체의 코드 수정 능력을 입증하지 않는다.

## 기존 기반과 공백

- PR #25에서 여섯 역할의 정의·설정 검증·조회 API·기준선 수집 도구가 dev에 병합되었다.
- 기존 대화·기억·문서 검색·승인 기반 격리 코드 테스트·Worker 상태/취소·GitHub CI를 재사용한다.
- 역할 registry는 현재 `definition_only`이며 실행/스케줄링은 비활성이다. 실제 웹 도구·파일 편집·개발 작업 상태·코딩 하네스 연결은 후속 구현이다.
- 기존 개발/운영 checkout과 실행 이미지에 차이가 있으므로, 대상 baseline과 허용된 worktree를 작업 시작 시 고정한다. 기존 dirty checkout을 개발 에이전트가 임의 정리하거나 운영에 복사하지 않는다.

## 개발 순서

| 순서 | 구현할 기능 | 확인할 결과 |
|---|---|---|
| D0 | 개발자 모드 계약·현재 모델/소스 기준선·고정 코딩 과제 | 대상 repo/base commit/task owner·변경 가능 경로와 금지 경로 식별. 실제/모의 결과 분리 |
| D1 | 소유자 전용 개발 대화·작업 생성/상태·중단 | 사용자가 대화로 지시하고 계획·진행·질문·실패를 확인. 일반 대화 경로 유지 |
| D2 | 작업별 웹 읽기 도구 | 외부 공식 문서·GitHub 등의 URL/본문/조회 시각을 근거로 반환. 읽지 않은 사이트를 읽었다고 주장하지 않음 |
| D3 | 독립 worktree의 파일 탐색·읽기·수정·diff | Role-AI 자신의 허용 저장소에서 요청한 파일의 실제 변경 확인. 읽기 전용 탐색과 쓰기를 분리 |
| D4 | 격리된 테스트/린트·결과 검증·제한된 복구 | 실제 exit code·출력·검증 결과를 사용. 실패 시 상한 안에서 수정 후 재검증하거나 실패를 보고 |
| D5 | GitHub branch/commit/PR·CI·dev 병합·체크포인트 | 작업과 diff에 결합된 권한으로 PR 생성. 검사·충돌·검토 확인 후 기존 정책에 따라 dev 병합 |
| D6 | 실제 모델 성능·전체 흐름 검증·회귀 | 사용자 지시부터 검증된 변경까지 실제 Role-AI 경로에서 재현. 품질·시간·토큰·자원·실패/재시도 기록 |

D0~D6는 한 번에 모두 활성화하지 않고 작게 검증해 PR로 연결한다.
개발자 모드의 작업 화면은 D1부터 최소 범위로 만들고, 전체 운영 UI 완료를 기다리지 않는다.
웹을 수동으로 읽는 기능과 정기 대량 수집은 구분하며, D2 때문에 전체 데이터 레이크 개발을 앞당기지 않는다.

## 실행·권한 계약

1. **인증과 지시:** 로컬 소유자의 인증된 개발자 모드 요청을 작업의 권한 근거로 사용한다. 사용자 지시/도구 결과/웹 문서/모델 추측을 구분한다. 모델이 생성한 승인 문구나 JSON을 실제 승인으로 취급하지 않는다.
2. **분리된 실행:** 대화 Gateway의 `tools.deny=["*"]`를 유지한다. 개발 작업은 별도 허용 도구/격리 Worker 경계로 연결하고 PC 제어 Gateway를 범용 셸로 재사용하지 않는다. OpenClaw를 연결할 때는 설치 schema와 실제 structured tool call 계약을 검증한다.
3. **개발 대상:** 서버가 등록한 Role-AI repo와 독립 worktree만 허용한다. API가 임의 호스트 경로를 받지 않으며 경로 탈출·symlink·다른 사용자/프로젝트 접근을 차단한다. 실행 중인 운영 소스, 사용자 DB/업로드, `.env`/키, Docker socket, 시스템 경로는 편집 대상에서 제외한다.
4. **도구 호출:** read/search/fetch/patch/test/Git 작업의 입력·대상·상한을 구조화하고 서버에서 검증한다. 모델 출력 셸 문자열을 그대로 호스트에서 실행하지 않는다. 조회·편집·테스트·PR·병합·배포 권한을 분리한다.
5. **웹 읽기:** 공개 문서 조회를 먼저 지원한다. URL/redirect/DNS 대상 검사, 내부망·metadata endpoint 접근 제한, 응답 크기/시간/콘텐츠 종류 제한을 실제 도구 계층에 둔다. 문서의 지시를 실행하지 않고 토큰·비공개 코드·개인 대화를 웹 요청에 자동 첨부하지 않는다. 로그인/제출/파일 업로드 같은 웹 쓰기는 초기 범위 밖이다.
6. **검증과 복구:** 변경 전후 소스 hash와 diff를 보존하고 테스트는 격리 환경에서 실행한다. 테스트 내용을 바꿔 구현 오류를 숨기지 않으며, 모델 재시도 횟수·전체 단계·시간을 제한한다. 되돌리기는 이 작업의 변경만 대상으로 하며 동시 사용자 수정을 덮어쓰지 않는다.
7. **GitHub:** 최신 dev를 기준으로 작업 브랜치를 만들고, 정해진 저장소·base·작업에 대해 PR을 만든다. 사용자 지시 범위와 기존 상시 승인 정책 아래 검사/충돌/검토가 통과한 변경만 dev에 병합한다. 모델이 CI 성공이나 권한을 스스로 선언해 병합 gate를 통과할 수 없게 한다. main 직접 반영은 하지 않는다.
8. **별도 승인:** 운영 배포·DB migration·환경변수/Gateway/보안 정책·도구 접근권한 확대·모델 설치/교체·실제 학습은 기존처럼 별도 승인한다. 일반 개발 코드 수정 권한이 이 권한을 포함하지 않는다.
9. **자원:** GPU 모델 추론은 초기 동시 1개로 제한하는 실행 계약을 두고 기존 대화와 충돌을 검사한다. 여섯 역할을 모두 켜거나 모델을 동시에 상주시키는 것을 선행 조건으로 삼지 않는다. 현재 모델을 유지하고 모델/추론 수준 후보 변경은 실측과 승인 후 반영한다.

## 완료 판정

다음은 목표이며 이번 우선순위 문서 변경으로 완료한 항목이 아니다.

- 사용자가 Role-AI 화면에서 대화로 개발 지시를 내리고 에이전트가 그 작업을 이어간다.
- 에이전트가 실제 외부 문서를 읽고 정확한 URL·근거를 답변에 연결한다.
- Role-AI 자신의 허용된 개발 worktree에서 실제 파일을 수정하고 diff를 표시한다.
- 테스트/린트가 실행되고 원본 결과와 실제 종료 코드가 작업에 연결된다. 실패 시 복구 또는 한계/실패를 정직하게 보고한다.
- 해당 변경으로 GitHub PR이 생성되고 CI를 확인한 뒤 정책에 맞게 dev 병합된다. 실행 중인 서비스는 승인 없이 교체하지 않는다.
- 미인증·비소유자·경로 탈출·문서 속 악성 지시·가짜 도구 성공·가짜 승인·테스트 우회·취소/timeout·동시 변경을 검사한다.
- 고정 과제는 문서 변경, 단일 함수 오류, 여러 파일 기능, 테스트 실패 후 복구, 웹 근거가 필요한 변경을 포함한다. 공개 연습 과제와 숨김 검증 과제를 분리한다.
- 실제 설치 모델과 실제 Role-AI 도구 경로를 통해 평가한다. 모델 응답을 모의한 계약 테스트와 실제 도구/실제 모델 E2E를 따로 보고한다.
- 지시 이행·수정 정확도·테스트 통과·작업 완료율·허위 성공·인용 정확도, TTFT/전체 시간/토큰/VRAM·RAM과 재시도를 기록한다. 채택 기준은 고정 기준선 측정 후 결정하며 미측정 개선율을 약속하지 않는다.

## 뒤로 이동하는 작업

대규모 외부 지식 수집/Raw 데이터 레이크, 일반 개인화·Hybrid RAG 확장, 여섯 역할 전체 오케스트레이션,
SFT/DPO/QLoRA 등 실제 학습, 전체 운영 대시보드는 개발자 모드의 최초 완료 이후로 옮긴다.
개발자 모드에 직접 필요한 좁은 범위의 근거 보관·작업 기억·실행 큐·최소 UI만 먼저 구현한다.
보안·인증·원본 보존·독립 테스트는 우선순위 변경과 관계없이 각 단계의 완료 조건이다.
