# MASTER_PLAN — Role-AI 통합 목표와 개발 방향

**버전:** 공유 문서 초안 1.0 (2026-10-29)  
**상태:** 방향 확정 / 세부 설계·구현 검증 진행 중  
**범위:** 기존 v1.5 대화 기획의 핵심 요약. 상세 계획은 기존 docs 및 원본 기획서 참고.

## 1. 제품 비전

개인 Windows PC + WSL2 Ubuntu 기반으로 운영되는 로컬 우선 AI 비서/개발 플랫폼. 브라우저(외부·모바일 포함), 장기적으로 전용 Windows 앱, 음성 입력, 안전한 Windows 작업 지원. Assistant가 오케스트레이션을 담당하고 Coding, Testing, Planning, Research, Security, Knowledge, Learning, Evaluation, UI 등 역할을 **필요할 때만 선택**하여 수행한다. 역할 하나당 별도 상주 LLM은 요구하지 않는다.

기존 환경(과거 확인): FastAPI, Docker, Ollama, OpenClaw, Cloudflare Tunnel/Access, RTX 4060 Ti 8GB. 운영 상태/버전은 작업 시 재확인.

## 2. 아키텍처

사용자 요청 → 인증/프로젝트 접근 확인 → 규칙 우선 Decision Layer(필요시 기존 Qwen) → Assistant/Task Contract → 승인된 도구 또는 역할 Agent → 기본 검증 → 위험도 기반 Adaptive Critic → 결과/검토 로그 → 사용자 확인.

- **Decision Layer:** 단순 분류 Python 규칙 우선, 불확실하면 기존 Qwen. Jev 등 Decision AI는 독립 비교 이후 채택 여부 결정.
- **계약/권한:** 목표, 범위, 허용 자원·도구, 검증 조건, 예산, 위험도, 승인, 중단 조건. 모델 출력은 실행 권한이 아님.
- **데이터:** 사용자/프로젝트별 기본 격리, 명시적 공통 공유만 허용. 과거 무프로젝트 자료 자동 공개 금지.
- **자원:** 8GB GPU 메모리 고려, 역할 간 모델 공유·추론 큐·예산 제한. 전체 모델 무조건 상주 금지.
- **검증:** 실제 테스트·근거·재현성 우선. 같은 모델에서 역할을 바꾼 검토는 독립 실험이라고 주장하지 않음.
- **실행:** Git/원본/DB 보호, 격리 Docker, 위험 작업 승인, 재시도 한도, 취소·복구·감사.
- **보안:** 추후 정적 분석/종속성·시크릿 검사, 허가된 격리 모의침투. 운영·타인 시스템 공격 금지.

## 3. Planning & Foresight Agent

요구 분석 → 실제 코드/문서 근거 수집 → 요구사항 추적 → 초안 작성 → 정상/부분 실패/최악 결과 예측 → 전문 비판 → 수정 위치·원인·재검증표 → 최종 통합 기획. 구별된 최소 10개 관점의 재검토 기록. 논리적 예상과 실제 실행 결과를 명확히 분리. 기획서 작성이 코드 변경 승인은 아님.

## 4. Adaptive Critic

각 역할의 **전담 검토 정책**을 공통 Reviewer가 적용하되, 낮은 위험에는 정적 도구/체크리스트만 사용. 중요한 설계는 별도 검토와 독립 근거, 치명적 위험은 승인 전 중단. 공개된 전문가 방법론은 출처/한계를 표기한 Perspective Library로 보관하며 실제 인물 참여·동의로 표현하지 않는다.

## 5. Technology Discovery & Validation

GitHub/Hugging Face/논문·공식 문서 탐색 → 출처·라이선스 검증 → 기존 기능 중복·8GB 호환성 평가 → 필요 후보만 격리 실험 → 실제 성공률·지연·비용·GPU 피크·안전 검토 → 사용자 채택 승인.

후보 상태: 미검증 / 조사 중 / 실험 대기 / 실험 통과 / 도입 승인 / 보류 / 제외. 탈락/보류는 삭제와 동일하지 않으며 새 정보가 있으면 재검토 가능. 모델 성능·라이선스·공개 상태는 발견 시점마다 다시 확인.

## 6. 개발 순서

| 단계 | 범위 | Gate |
|---|---|---|
| P0 | 구현 현황 감사·범위/권한·요구 추적·브랜치 비교 | 현재 코드에 고정된 근거와 변경 범위 확정 |
| P1 | 최소 Task Contract·권한/프로젝트 격리·작업/복구 | 허용 범위 밖 접근 차단, 기존 동작 회귀 검사 |
| P2 | 안전한 Coding 벤치마크; Role-AI + 소형 프로젝트 혼합 | 공개/숨김 평가 분리, 재현 가능한 성능 보고 |
| P3 | Planning/Adaptive Critic 프로토타입 | 실제 요구 누락 및 유효 결함 탐지 효과 평가 |
| P4 | 조건부 검색·Decision·tool AI/보안 기능 확장 | 기존 기준선 대비 유용성 확인 |
| P5 | 경험 학습·장기 UI/Windows·음성·자율 개선 | 보안 승인·홀드아웃·롤백·사용자 가치 실측 |

## 7. 최근 Codex 감사의 알려진 과제

2026-10-29 제공된 감사 문서(기준 dev `a6e873c099a8a7af990ecd23b6d84d5b5fddaa5a`, **실제 테스트 미실행**)에 따르면:
- Coding Agent 루프·격리·승인 기능은 일부 구현, 일반 Agent Registry는 `definition_only`.
- 일반 Task Contract/PermissionGate/실행 스케줄러는 일관되게 연결되지 않음.
- Coding 벤치마크는 5개 합성 과제이며 독립 숨김 평가가 없음. `--host-runner` 위험, 전체 모델 unload, GPU 측정 실패 기록 문제 지적.
- 일반 Ollama 긴 Planning 결과를 위한 토큰·컨텍스트 및 분할 생성 필요성 지적.
- Draft PR #32는 Planning Skill 후보이며, 사용자의 자동 병합 승인이 없음.

위는 감사 시점 주장으로 현재 최신 구현과 반드시 대조한다. 상세 근거: [기존 Coding Agent 문서](../../coding-agent-stabilization.md).

## 8. 장기 영역

- RAG/대화·작업 기억: 동의·기간·프로젝트 범위·삭제·출처 관리.
- Coding/Testing/Review: PR 이전 테스트·독립 평가·변경 영향.
- 학습: 검증 데이터 축적·중복 제거·원본 압축 관리·승인된 선택적 미세조정·회귀·롤백.
- UI: 승인된 아이소메트릭 픽셀아트 방향과 PC/모바일 분리. **UI 변경 전 이미지 시안 승인 필수.**
- Windows: OpenClaw Companion 및 승인 기반 제어. 로컬 PC의 모든 실행 권한을 무제한 부여하지 않는다.
- Cloudflare: 외부 브라우저 접근, 접근 제어와 운영 분리.

## 9. 기획 품질 정책

최소 10개 관점(요구사항, 논리, 사실, 실현성, 아키텍처, 보안, 복구, 자원, 가장 강한 반론, 최종 통합)에서 **구체적 발견·수정·잔여 위험** 기록. 최소 회수는 품질 보증이 아니며, 미실행 테스트·예측 수치를 실측으로 둔갑시키지 않는다.

## 10. 작성·개발 승인 경계

문서에 적힌 기능은 **기획**이지 모두 구현된 기능이 아니다. Codex/ChatGPT 누구도 사용자의 명시적 실행 요청 없이 코드·PR·배포를 진행하지 않는다. 비밀정보, 운영 데이터, 기존 Render 서비스 유지.
