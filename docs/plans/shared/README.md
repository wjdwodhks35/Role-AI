# Role-AI 공유 기획 허브

> 2026-10-29 / 문서 관리 초안 / **기획과 구현 승인은 서로 다름**

이 폴더는 회사·모바일에서 ChatGPT와 구상한 아이디어와, VS Code Codex의 개발 결과를 공유하기 위한 **단일 문서 기준점**이다. 원문 대화 자동 동기화는 지원하지 않는다. 새 내용을 실제로 공유하려면 해당 문서 변경을 GitHub에 반영해야 한다.

## 파일 지도

| 파일 | 목적 | 누가/언제 갱신 |
|---|---|---|
| [IDEA_INBOX.md](IDEA_INBOX.md) | 미확정 제안·검토 대기 | 아이디어를 발견할 때 |
| [DECISIONS.md](DECISIONS.md) | 확정된 결정·변경 이유·승인 경계 | 사용자가 결정을 확정할 때 |
| [MASTER_PLAN.md](MASTER_PLAN.md) | 목표 구조·단계별 로드맵·장기 범위 | 승인된 중요한 설계가 변경될 때 |
| [DEV_STATUS.md](DEV_STATUS.md) | 근거 있는 구현 상태·테스트·후속 작업 | Codex 작업 완료 및 검증 뒤 |

기존 설계 자료: [기존 계획 목록](../), [Coding Agent 설계](../../coding-agent-stabilization.md), [아키텍처](../../architecture.md). 채팅에서 작성한 v1.5 문서 10개는 별도로 전달된 기획 초안이며, 이 폴더의 MASTER_PLAN은 동기화를 위한 **요약 기준 문서**다. 문서 사이 내용이 충돌할 때는 최신의 명시적 사용자 결정, 실제 검증된 코드 상태를 우선 확인한다.

## 표준 운영 흐름

1. ChatGPT와 토론한 새로운 내용은 먼저 IDEA_INBOX에 등록한다. 확정 여부를 임의 판단하지 않는다.
2. 최소 10개의 **서로 다른 검토 관점**(요구, 모순, 출처, 현실성, 아키텍처, 보안, 복구, 자원, 반론, 통합)을 거쳐 발견 사항·수정·잔여 위험을 기록한다. 10회 실제 독립 실험이라고 주장하지 않는다.
3. 사용자가 선택을 명시하면 DECISIONS에 날짜·선택·이유·대안·적용 범위를 기록하고 MASTER_PLAN을 갱신한다.
4. Codex는 작업 시작 전에 이 네 파일을 읽고 현재 저장소 및 작업 트리 상태를 비교한다.
5. Codex는 승인된 작업 범위에서만 구현한다. 테스트와 문서 결과를 DEV_STATUS에 근거와 함께 남긴다.
6. ChatGPT는 GitHub에 반영된 최신 내용을 읽어 후속 기획을 논의한다. **채팅 대화 자체가 실시간 동기화되지는 않는다.**

## 안전 규칙

- 일반 토론, 기획, 이슈 정리 = **코드 변경 승인 아님**.
- 코드 변경·GitHub 쓰기·PR·병합·배포·DB/비밀키/운영 서버 변경은 사용자 승인 범위 확인. 이 문서가 권한을 부여하지 않는다.
- 운영 데이터·다른 프로젝트·기존 Render 서비스 유지. Windows/OpenClaw 권한 임의 확대 금지.
- UI 변경은 먼저 시각 시안을 만들고 사용자 승인 후 코드 수정.
- 데이터는 **프로젝트별 기본 격리**, 지정 자료만 명시적으로 공통 공유.
- 발견한 기술은 넓게 기록하되, 도입은 검증·승인 이후.
- 실제로 실행하지 않은 테스트 및 미검증 모델 성능을 '통과'로 기록하지 않는다.
- 기밀·API 키·인증 토큰·개인정보를 문서나 커밋에 포함하지 않는다.

## 기록 관례

각 아이디어/결정/작업에는 `IDEA-###`, `DEC-###`, `TASK-###` ID를 부여한다. 날짜(Asia/Seoul), 상태, 근거 링크나 커밋, 관련 ID를 남긴다. 채팅에서 언급된 계획이 실제 dev에 존재하는지 별도로 검증한다.
