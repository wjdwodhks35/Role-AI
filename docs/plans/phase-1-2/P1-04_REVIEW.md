# P1-04 — 자료 경로·대화 고정·보관 처리

시작 dev: `89f61c4502e702b7dcf527d665ade198909f41c5` (P1-03 PR #37).
사용자는 2026-10-30에 삭제 정책 **1번 보관 처리**를 확정했다.
원본·출처를 보존하면서 목록·검색·내보내기·모델 활용에서 차단한다. 영구 삭제나 보관 해제는 추가하지 않는다.

## 구현과 수용 기준

- v5는 `scope_archives`, `scope_conversation_bindings`, `scope_conversation_sources`와 해당 무결성 트리거만 추가한다. 기존 테이블 열/본문은 바꾸지 않는다.
- 기존 v4 DB는 명시적 오프라인 이행이 필요하다. 실제 운영 이행은 실행하지 않았다. v5는 기존 대화를 자동 바인딩하거나 이관하지 않는다.
- 문서·기억 생성 시 현재 범위/버전을 기록한다. 기본 읽기 범위는 개인 보관함이며 동일 사용자 소유 프로젝트도 명시적 정확 버전 Grant 없이는 읽지 않는다.
- 문서 목록/직접 ID/export/키워드/의미 검색과 기억 검색/문맥/export는 같은 P1-02 적격성 및 P1-03 Gate를 사용한다. DB에서 보관/범위를 먼저 거르고 응답 전 현재 권한을 확인한다.
- 기억 목록의 원소유 범위 후보 검토는 소유자 관리 경로다. 후보/검토 필요 기록은 모델 문맥과 export에 사용하지 않는다. 새 Agent 도구를 추가하지 않는다.
- 현재 자료·버전·Grant·파생 출처를 체크한다. 임베딩 전 후보를 거르고 완료 후 재검사한다. 모델 실행 중 철회 시 응답/대화 저장을 거부한다. 이미 전달한 모델 입력을 소급 회수할 수는 없다.
- DELETE는 원문·조각·기억 수정 이력·버전·출처를 물리 삭제하지 않고 불변 보관 표식과 권한 세대를 기록한다. `204`와 `X-Role-AI-Removal: archived`를 반환한다. 원소유 범위에서 멱등이고 읽기 공유만 받은 범위의 변경/보관은 거부한다.
- 재업로드는 새 ID를 만들며 과거 Grant를 승계하지 않는다. 보관된 자료는 활성 문서 개수 한도에서 제외한다. 보관 본문의 저장 공간·보존기한/영구 삭제는 후속 정책이다.
- 새 대화의 프로젝트 ID와 정책 세대를 생성 시 고정한다. 다른 프로젝트/바뀐 정책/사용 불가 출처는 새 대화를 요구한다. 과거 대화는 소유자 보관 기록으로 조회할 수 있지만 모델 문맥으로 재사용하지 않는다.
- 기억 추출의 프로젝트/원문은 검증된 대화에서 정한다. 모델이 제안한 프로젝트·expiry·출처는 신뢰하지 않는다. 파생 기억에 대화의 자료 의존성을 승계한다.
- 자료 소속은 P1-02의 불변 ID 정책을 유지한다. 다른 프로젝트에는 새 기록을 만들며 기존 기억의 소속/원문 출처를 덮어쓰지 않는다.
- P1-05의 Task별 실행 승인·도구 권한과 세션 명시 결합, P1-06 이후 실행/복구는 아직 구현하지 않았다.
