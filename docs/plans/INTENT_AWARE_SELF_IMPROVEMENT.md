# Role-AI 기획 추가안 — 의도 인식형 다중 Agent 자기 개선

> 상태: **기획 전용 / 미구현**  
> 우선순위: 토큰 절약·무손실 압축 및 성능 측정 자동화 이후  
> 범위: 오류 발견 → 의도 확인 → 다중 관점 토론 → 증거 기반 판단 → 승인된 수정 제안

## 목적
Role-AI가 스스로 코드나 동작의 이상을 발견하더라도 즉시 수정하지 않는다. 기존 요구사항, 설계 의도, 테스트, 보안 정책과 변경 이력을 검토하고, 복수의 독립 관점으로 토론해 **실제 결함 / 의도된 동작 / 근거 부족**을 구분한다.

## 예정 절차
1. **후보 탐지:** 실패한 테스트, 성능 회귀, 오류 로그, 정적 분석 결과에서 이상 징후 수집. 스타일 차이만으로 버그로 단정하지 않음.
2. **의도 추적:** 요구사항·설계 문서·커밋/PR 기록·기존 테스트·보안 정책·사용자 승인 사항을 우선 확인. 출처와 버전 해시를 남김.
3. **조건부 토론:** 의도가 명확하면 불필요한 LLM 토론 생략. 불명확하고 영향이 있는 경우에만 제한된 횟수로 독립 역할 검토.
   - 결함 분석: 재현 가능한 실패와 영향 제시
   - 설계 옹호: 의도된 동작이라는 반론과 근거 제시
   - 회귀/보안 검토: 수정 시 위험 및 기존 계약 위반 검토
   - 검증 담당: 서로의 주장에 필요한 최소 독립 테스트 제안
4. **판정:** (a) 수정 제안 (b) 의도된 동작 유지 (c) 추가 검증 필요. 다수결이나 모델의 자신감만으로 자동 수정하지 않음.
5. **격리 실험:** 수정이 필요하다는 증거가 확보되면 별도 작업 브랜치/격리 환경에서 최소 패치 및 회귀·보안 테스트 수행.
6. **승인 및 반영:** 사용자 승인 전에는 운영 코드, DB, 인증, 배포, 모델 가중치 변경 금지. 승인 후에도 독립 검증과 롤백 가능성 확인.
7. **보상·학습 연결(장기):** 검증된 결과만 평가 데이터로 기록. 자기 평가만으로 학습 보상을 확정하거나 모델을 자동 승격하지 않음.

## 토큰 절약 원칙
- 기존 테스트·정적 검사·문서 검색을 우선 사용하고, 토론은 조건부로만 실행.
- 역할별 동일한 최소 근거 패킷 제공, 응답 JSON 제한, 최대 호출/토큰/시간 예산 설정.
- 같은 증거 해시의 재평가 결과 캐시; 관련 없는 전체 파일·전체 로그 재주입 금지.
- 상충하는 주장이 나오면 무한 토론 대신 독립 테스트 또는 사용자 판단으로 이관.
- 성능 측정: 발견 정확도, 오수정 제안율, 실제 회귀율, 작업당 모델 호출 수·토큰 수, 실행 시간.

## 단계별 완료 기준
- Phase A: 기획·평가 기준·의도 판별 테스트 시나리오 확정
- Phase B: 읽기 전용 탐지 및 근거 수집
- Phase C: 제한된 다중 관점 토론과 감사 로그
- Phase D: 격리된 수정 제안 및 회귀 검증
- Phase E: 승인 기반 반영 및 검증된 보상 이력 연계

## 제외 범위
현 단계에서 새 MCP/A2A 연결, 자율 코드 수정, 자동 PR/병합, 운영 배포, 무인 강화학습은 수행하지 않음.

## 관련 계획
- 최우선: 토큰 사용량 최소화, 정확 복원 가능한 저장 압축, 실제 성능 벤치마크
- 별도 UI 브랜치: `feature/pixelqg-agent-ui` (상태 시각화 UI 시안)
