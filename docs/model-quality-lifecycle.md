# 전체 검수 · 평가 · 배포 후보 관리

선택하여 실제 보관한 학습·평가 샘플 모두를 Teacher와 Reviewer가 행별로 검수합니다.
최대 100행이며 Hugging Face 원본 전체를 내려받거나 검수하지 않습니다.
샘플별 pass/reject·근거·위험과 통과율을 저장합니다. 위험이 하나라도 있으면 단계는 reject입니다.
모델 판단은 정확도 인증이 아닙니다. 오류 시 부분 검수를 전체 통과로 저장하지 않습니다.
로컬 검수 범위가 3개였던 기존 데이터는 Teacher/Reviewer를 다시 검수한 뒤 승인하세요.
수동 GPT 검수는 기존대로 3개 미리보기와 별도 비용 동의입니다.
자동 허용 GPT는 기존대로 선택된 전체 최대 30개이며 유료 호출은 opt-in입니다.
수집 Worker 전체 제한 600초 때문에 검수가 길어지면 실패로 남을 수 있습니다.

고정 평가 묶음은 2~10문항, 최대 20묶음으로 생성 후 불변입니다.
수동 승인 시 묶음을 선택하면 원문과 겹치는 질문을 거부하고 질문·해시를 승인 계획에 고정합니다.
GPU Worker는 학습 전후 같은 역할 프롬프트, greedy 생성 최대 128토큰,
NFKC·대소문자·공백 정규화 exact match 및 held-out loss를 기록합니다.
질문이 문맥 길이를 초과하면 실패하며 임의로 자르지 않습니다.
자유형 답변의 의미 일치·다른 능력 퇴행을 판단하지 못합니다.
자동 승인 학습 계획에는 아직 평가 묶음을 연결하지 않으므로 loss만 평가합니다.

평가된 작업이 모델 버전입니다. 실제 GPU 결과의 adapter 파일 해시와 데이터 해시를 보관합니다.
배포 후보 선택은 로컬 소유자만 가능하고 파일 재검증, 고정 평가 점수 및 loss 무퇴행을 요구합니다.
Fake Trainer·평가 없는 버전은 후보 선택이 차단됩니다.
선택 및 이전 후보 되돌리기는 DB 이력과 revision CAS로 충돌을 방지합니다.
이 기능은 배포 후보 레지스트리이며 현재 Ollama 채팅 모델의 적용/실제 서비스 롤백은 수행하지 않습니다.
Ollama 어댑터 변환·호환성 검증과 수동 배포 실행은 후속 단계입니다.
데이터 또는 모델 파일을 삭제하면 해당 후보의 재선택/되돌리기는 차단됩니다.

통합 현황은 수집 계획·학습 작업·GPT 심사 기록을 사용자별로 모읍니다.
Worker heartbeat나 실제 진행률은 아직 제공하지 않으며 저장된 running 상태는 온라인 증명이 아닙니다.
학습 중 취소와 배포 자동 활성화는 지원하지 않습니다.

새 환경변수나 유료 서비스는 필수가 아닙니다.
실제 Ollama 검수 품질과 GPU 학습/생성은 서버·모델이 준비된 뒤 별도로 검증해야 합니다.
