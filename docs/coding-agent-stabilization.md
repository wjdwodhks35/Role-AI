## 2. 실제 확인한 원인 (기존 벤치마크 원문 응답 기준)

1. **thinking 출력 예산 소진**: qwen3 계열은 `think`를 지정하지 않으면 thinking에
   `num_predict`(1024)를 모두 사용해 `content`가 비었다. 실측: qwen3:4b thinking 3,978자, 출력 1,024토큰, 본문 0자.
2. **같은 파일 다중 수정 거부(Agent 버그)**: qwen3.5:4b T3는 stats.py에 정확한 수정 2개를 보냈으나
   Agent가 같은 경로 FileChange 2개를 만들어 작업공간 보안 검사("수정 수 한도")에 걸려 작업 전체가 실패했다.
   두 번째 수정이 원본 기준으로 계산되는 버그도 있었다.
3. **`\\n` 이중 이스케이프 + 첫 패치 실패 시 작업 종료**: qwen2.5-coder:3b, qwen3:8b가 old_text에
   literal `\n`을 넣어 정확 일치가 실패했고, 이 오류 하나로 작업이 `failed` 처리됐다.
4. **최근 관찰 2개만 전달**: 이미 읽은 파일·계획을 잊고 read↔plan을 24단계까지 반복했다.
5. **프롬프트 placeholder 복사**: qwen3:8b가 예시의 `relative_path`를 실제 경로로 사용했다.
6. **매 호출 모델 재로딩**: `keep_alive: 0`으로 호출마다 4~9초 로딩.
7. **예약 토큰만 기록**: 호출마다 5,120토큰 예약, 실사용 미기록.

### 유지한 안전 정책
- 범위 밖 파일·테스트 파일 수정은 **즉시 실패**(복구 대상 아님). 작업공간 경로 중복 검사도 그대로.
- 테스트 통과 증거 없는 finish는 거부(이제 복구 가능 오류로 알려주지만 completed는 불가).
- 같은 거부가 `same_error_limit`(기본 2)번 반복되거나 `tool_error_limit`(기본 4) 초과 시 중단.
- 같은 행동 3회 또는 코드 변경·테스트 없이 8단계면 중단(무한 재시도 없음).
- 호출 전 예약 → 저장 → 호출 순서 유지. Ollama가 입력·출력 토큰을 **둘 다** 보고한 경우에만 실사용량으로 정산. 응답 유실·crash·미보고는 예약량 그대로 청구.
- GPU 관리 정책이 켜져 있으면 keep_alive는 강제로 0(기존 대화 경로와 같은 규칙). 작업 종료 후에는 **이미 올라간 경우에만** 모델 보존 시간을 바꾸거나 내림(새로 로딩하지 않음).
