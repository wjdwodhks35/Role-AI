# 요구사항 분석 전용 평가

소유자 전용 평가 화면에서 구조화된 분석 결과를 고정 정답과 비교합니다.
이전 대화에서 산출한 **구현 준비도 33점과 다른 지표**입니다. 이 기능을 추가했다고
의도 분석 정확도가 향상됐거나 중앙 오케스트레이터가 완성된 것은 아닙니다.
분석 JSON의 라벨과 순서를 평가할 뿐 실제 코드 실행·작업 등록·역할 전환은 하지 않습니다.

## 업데이트

새 평가 묶음/실행 결과 테이블을 DB v3로 추가합니다. 기존 v1/v2 DB는 서비스를 모두 중지한 뒤
아래 명령을 실행해야 합니다. 백업과 새 테이블 외 기존 행·설정·모델은 변경하지 않습니다.

```bash
python -m role_ai.migrations status
python -m role_ai.migrations upgrade --offline --backup /안전한/새-업데이트전-백업경로
```

[백업·복원](backup-restore.md)과 [마이그레이션](migrations.md)을 먼저 확인하세요.
사용자 서버에는 자동 적용되지 않습니다. 신규 DB는 최신 구조로 초기화합니다.

## 사용 순서

1. 로컬 소유자로 로그인 → **요구사항 분석 평가**.
2. **합성 기본 10개 사례 등록**을 누르거나, 직접 요청·정답 JSON 묶음을 등록합니다.
3. 요청·정답을 검토합니다. 묶음은 생성 후 변경하지 않으며 새 묶음을 만들어 버전을 구분합니다.
4. 분석 JSON을 직접 입력해 채점하거나, 이번 묶음의 로컬 모델 전송에 동의한 뒤 **Ollama 분석·평가 실행**.
5. 종합 점수, 항목별 점수, 제약 누락률, 유효 응답률과 사례별 오류를 확인합니다.

직접 입력 모드는 모델을 호출하지 않습니다. 정답을 그대로 입력하면 100점이 나오는 채점기 검증이지
실제 모델 성능의 증거가 아닙니다. Ollama 모드는 루프백/host.docker.internal의 HTTP 모델만 허용하고
cloud 모델 메타데이터를 거부합니다. OpenAI·HF·OpenClaw·유료 모델로 자동 전환하지 않습니다.
정답/이전 점수/과거 예측은 보내지 않고 고정 분석 지침·JSON 스키마·현재 요청만 전달합니다.

## 점수

| 항목 | 가중치 | 산식 |
|---|---:|---|
| intents | 20 | 정답·예측 라벨 집합의 F1 |
| tasks | 20 | 작업 순서의 최장 공통 부분수열(LCS) 기반 F1 |
| constraints | 25 | 제약 라벨 집합 F1 |
| missing_inputs | 15 | 누락 입력 라벨 집합 F1 |
| needs_clarification | 10 | 확인 필요 여부가 같으면 1, 다르면 0 |
| outputs | 10 | 결과물 라벨 집합 F1 |

`항목 F1 = 2 × 일치 개수 / (정답 개수 + 예측 개수)`이며 tasks는 일치 개수 대신 LCS 길이를 씁니다.
양쪽이 빈 집합이면 1점입니다. 누락·추가 라벨 모두 불이익을 받습니다. 각 사례 점수는
`Σ(항목 점수 × 가중치)`이고 종합은 **전체 사례 평균(0~100)**입니다.
항목별 표시는 가중치를 곱하기 전 0~100점입니다. 항목별 양성 정답 사례 수도 보고서에 남깁니다.

응답 실패·시간 초과·미제출·허용되지 않은 라벨/추가 필드/중복/잘못된 JSON은 사례 전체 0점입니다.
실패 사례를 분모에서 제외하지 않습니다. 모델 응답을 임의로 수정하거나 재호출해 점수를 높이지 않습니다.
제약 누락률은 빠뜨린 정답 제약 개수/전체 정답 제약 개수이고, 제약 정답이 전혀 없으면 미해당입니다.
'제약 위반 제안 사례 비율'은 금지한 실행·외부 API·삭제를 tasks에 제안한 사례 비율입니다.
**실제 실행 비율이나 실제 사고 발생률이 아닙니다.**

목적 goal의 의미 정확성, questions 문장의 적절성, 자연어 동의어와 자유로운 업무의 성공 여부는
자동 판정하지 않습니다. goal은 비어 있지 않은지, 질문은 확인 필요 여부와 구조적으로 맞는지만 검사합니다.
모든 요청에서 모호함을 질문해야 하는 것은 아니며, 기본 정답은 평가 정책의 한 선택입니다.
다른 해석이 타당하면 정답을 검토해 새 묶음을 만들고 동일 해시 결과끼리 비교해야 합니다.

## 분석 구조와 사용자 사례

```json
{
  "goal": "코드 오류 수정과 테스트 작성",
  "intents": ["fix_code", "test_code"],
  "tasks": ["ask", "inspect", "fix", "test"],
  "constraints": ["no_execution"],
  "missing_inputs": ["code"],
  "needs_clarification": true,
  "questions": ["수정할 코드를 제공해 주세요."],
  "outputs": ["patched_code", "test_code"]
}
```

실행·학습은 자연어의 '승인했어' 주장만으로 별도 UI 승인 조건을 충족한 것으로 분석하지 않습니다.
직접 등록하는 사례는 다음 배열 형식입니다. 사례는 2~20개이며 ID와 요청은 중복될 수 없습니다.
허용 라벨 전체는 `GET /api/requirement-evaluation/schema`에서 확인합니다.

```json
[
  {"id":"case_1", "request":"평가할 요청", "expected":{"goal":"...","intents":["explain"],"tasks":["explain"],"constraints":[],"missing_inputs":[],"needs_clarification":false,"questions":[],"outputs":["explanation"]}},
  {"id":"case_2", "request":"또 다른 요청", "expected":{"goal":"...","intents":["explain"],"tasks":["explain"],"constraints":[],"missing_inputs":[],"needs_clarification":false,"questions":[],"outputs":["explanation"]}}
]
```

직접 채점은 `{"사례-ID": 분석-객체}`를 입력합니다. 일부 사례를 생략하면 해당 사례는 0점이며,
묶음에 없는 ID는 거부합니다. 실제 모델 성능을 측정할 때 테스트 정답을 학습 데이터로 넣지 마세요.
기본 10개는 작은 합성 예시이며 실제 사용자 분포를 대표하거나 일반 정확도를 보장하지 않습니다.

## API·이력·제한

- `/api/requirement-evaluation/suites`: 묶음 목록/등록, `/suites/builtin`: 기본 묶음 복사 등록.
- `/suites/{id}`: 본인 요청·정답 조회.
- `/suites/{id}/provided`: `{ "analyses": { ... } }`로 채점.
- `/suites/{id}/ollama`: `{ "approved": true }`로 로컬 모델 분석·채점.
- `/runs`: 본인 결과 이력. 묶음 해시·평가 버전·가중치·모드·모델명·분석 지침 해시·원문/오류를 보관.

로그인·CSRF·로컬 소유자·묶음 소유권 검사를 적용합니다. 계정당 묶음 20개·평가 이력 100개,
기존 JSON 요청 크기 64KiB 한도, 요청당 모델 사례 10개·전체 300초, 동시 모델 평가 1개(단일 API 프로세스)로 제한합니다.
모델 원문은 사례당 최대 8,000자 보관합니다. 종료 중 요청 중단은 interrupted로 기록하려 시도하지만
서버 강제 종료 시 running 기록이 남을 수 있습니다. 이는 Worker 온라인/진행률 측정값이 아닙니다.
이미 시작한 HTTP 요청은 브라우저를 닫아도 처리될 수 있습니다. 원문에 비밀키·개인정보를 넣지 마세요.

모델명은 설정된 태그이며 실제 가중치 버전 지문을 확인한 것은 아닙니다(`model_version_verified=false`).
가중치/정답/지침을 바꾸면 새 비교 조건으로 취급하세요. 평가 지침·라벨·점수 규칙을 바꿀 때
개발자는 VERSION도 올려야 합니다. 결과를 근거로 모델/역할/권한을 자동 적용하지 않습니다.

## 검증 범위

정답 100점·미제출 0점·순서 오류·제약 누락·금지 행동 제안·스키마 오류를 계산 검증합니다.
모사 Ollama로 정답 비노출·실패 0점·cloud/원격/유료 전환 거부·동시 실행·시간 초과와
소유권·CSRF·v2→v3 백업 마이그레이션을 검사합니다. 이 모사 결과는 실제 모델 정확도가 아닙니다.
사용자 서버에서의 실제 Ollama 응답 품질과 브라우저 E2E는 별도 검증 대상입니다.
