# Codex 토큰 사용 최적화

기존 VS Code Codex 채팅창을 유지한다. 프로젝트 지침으로 명령 선택을 유도하며, 확장 내부 패치·별도 AI 터미널·API 호출·MCP 추가·셸 전역 별칭은 사용하지 않는다. 사용자에게 매번 래퍼 명령을 입력하도록 요구하지 않는다.

## 자동 적용 범위

- 저장소의 `AGENTS.md`는 공통 규칙만 유지한다. Windows 도우미 규칙은 `tools/windows-launcher/AGENTS.md`로 분리했다. 관련 작업에서만 읽는다.
- Codex는 테스트·빌드의 일반 텍스트 로그를 `python3 tools/codex/run_logged.py -- <command> <args>`로 실행하도록 지시받는다. Windows 로컬 checkout은 설치된 `python`을 사용한다. WSL checkout은 WSL Python 사용을 권장한다.
- JSON·소스·diff·대화형 명령은 직접 실행한다. 래퍼도 짧거나 불확실한 출력은 유지한다. 지침을 따르지 않은 호출과 MCP/내장 읽기 도구는 압축되지 않는다. 도구 결과 전체에 대한 강제 가로채기는 구현하지 않았다.
- 현재 채팅에서는 변경된 지침을 읽고 사용했다. 새 세션의 자동 지침 로딩은 설치 CLI의 `codex -C <저장소> debug prompt-input`으로 별도 확인했다. 이미 열린 세션에 지침이 자동 재주입된다고 보장하지 않는다. 저장소 밖을 작업 루트로 사용하면 하위 저장소 지침이 자동 탐색되지 않을 수 있다.
- 프로젝트 지도 `CODEX_PROJECT_MAP.md`는 정적 목차다. 내용 변경 시 경로·명령을 함께 갱신하며, 지도 경로 존재 여부를 테스트한다. 자동 소스 캐시나 내용 해시 캐시는 도입하지 않았다.

## 로그 처리와 보안

- 표준 라이브러리 `subprocess`로 명령·인수를 직접 실행한다. 셸 파이프로 종료 코드를 잃지 않는다. POSIX 시그널 종료는 셸과 같은 `128 + signal`로 반환하며, 실행 파일 부재는 127이다. 사전 저장소 준비 실패는 125이며 명령을 시작하지 않는다.
- stdout/stderr는 병렬로 수집해 `.codex-local/logs/run-<임의값>/stdout.log`, `stderr.log`에 원본 바이트를 저장한다. 종료 코드·처리량·실행 시간·잘림 여부는 `result.json`에 남긴다. 출력에 재조회 경로를 표시하며 명령 인수는 메타데이터에 저장하지 않는다.
- 기본 상한은 스트림당 4 MiB다. 초과하면 앞부분과 끝부분만 상한 내에 보관하고, 유실된 중간 바이트 수를 명시한다. 상한 초과 로그는 전체 원본이 아니며 중간 진단이 빠질 수 있다. 꼭 필요한 경우 `--max-log-bytes`로 1 KiB~16 MiB 범위에서 조정한다. 무제한 수집을 주장하지 않는다.
- 다음 래퍼 실행 전 완료된 로그를 7일 보존/총 128 MiB 목표로 정리한다. 실행 중 폴더는 삭제하지 않아 동시 실행 중에는 총량이 일시적으로 커질 수 있다. 실행하지 않으면 기간이 지나도 자동 삭제되지 않는다. 별도 상주 프로세스나 스케줄러는 등록하지 않는다.
- POSIX 로그 디렉터리 0700·파일 0600을 사용한다. Windows는 PowerShell로 접근 SID를 조회하고 `icacls`로 현재 사용자 SID 외 접근 규칙과 상속을 제거한다. 관리자/SACL 권한은 요구하지 않는다. 기존 명시적 추가 권한도 남기지 않는다. 이 작업은 지정된 로그 폴더에만 적용한다. 로그 위치를 공유 폴더로 지정하지 않는다.
- 원본에는 비밀값·개인정보가 들어갈 수 있다. `.codex-local/`은 Git에서 제외한다. 원본을 커밋·업로드하지 않는다. 화면 출력은 일반적인 key/token/password, Bearer, OpenAI 키 형태와 이메일을 휴리스틱으로 가리지만 모든 비밀·개인정보 탐지를 보장하지 않는다. 비밀을 출력하는 명령 자체를 피한다.
- ANSI·알려진 성공/진행 행만 줄인다. 실패·경고·Assertion·Traceback·알 수 없는 문장은 보존한다. 짧은 출력은 ANSI 정리와 비밀 형태 가림 외에는 유지한다. 서로 다른 스트림 사이의 원래 시간 순서는 보존하지 않는다.

## 현재 설정 검토

2026-10-25 확인:

- WSL CLI: `0.164.0-alpha.11.1`; VS Code WSL 확장: `26.1021.22027`. Windows에도 같은 최신 확장 폴더 및 이전 버전 폴더가 존재한다. 실제 활성화 버전을 폴더 존재만으로 단정하지 않는다.
- WSL `~/.codex/config.toml`, 전역 `AGENTS.md`, 프로젝트 `.codex/config.toml`은 없었다. Windows 설정에는 모델 `gpt-5.5`, 추론 강도 `medium`, 명시적 MCP `node_repl` 1개가 있었다. 연결된 앱 도구 전체를 이 설정만으로 열거할 수 없다. 미사용 여부가 확정되지 않아 비활성화하지 않았다.
- 모델·추론 강도·승인·샌드박스·MCP·전역 설정은 변경하지 않았다. 단순 작업의 낮은 추론 강도 선택은 향후 선택 사항이며 자동 전환은 구현하지 않았다.
- 설치 CLI에서 hooks 기능 플래그는 stable/true다. 하지만 전역 명령 훅을 등록하거나 도구 출력 치환을 가정하지 않는다.
- `/compact`, `/status`, `/reasoning` 문자열은 설치 바이너리에 있지만 기존 VS Code 채팅에서의 명령 지원·효과는 실기 검증하지 않았다. 해당 명령을 자동 전송하지 않는다.
- 공식 설정의 `tool_output_token_limit`은 개별 도구 결과의 히스토리 저장 예산이며 의미 보존 요약 설정은 아니다. `model_auto_compact_token_limit`은 자동 문맥 압축 임계값이다. 필요한 오류가 잘릴 수 있어 임의로 낮추지 않고 기존 기본값을 유지했다.
- 전역 규칙 추가·MCP 축소·압축 임계값 변경은 이번 구현 범위에서 제안 사항으로만 남긴다. 기존 설정을 덮어쓰지 않았다.

공식 근거: [AGENTS.md 자동 탐색](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Codex 설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference). 표면·버전에 따른 지원 차이는 설치 환경에서 별도 검증해야 한다.

## 검증과 측정

검사: `python3 tools/codex/run_logged.py -- python3 -m unittest discover -s tools/codex/tests -v`. 성공/실패·stdout/stderr·한글·반복·긴 Traceback·원본 비밀값/출력 가림·상한·경로 충돌·보존·종료 코드를 확인한다. Python 설치만 필요하며 Role-AI 운영 서비스·DB·모델은 건드리지 않는다.

실제 토큰·cached input·도구 재시도·구독 한도 사용량은 이 래퍼에서 관측할 수 없다. 아래 측정은 문자 수·종료 코드·시간 비교이며 토큰 절감률이 아니다. 래퍼 실행 자체의 도구 호출은 기존 명령 호출 1회를 대체하지만 지침·래퍼 경로·요약 헤더의 문맥 비용이 추가된다. 짧은 로그에는 순절감이 없을 수 있다.


2026-10-25 측정(동일한 보조 도구 검사 16개를 각각 직접/래퍼로 1회 실행):

| 항목 | 직접 실행 | 래퍼 실행 |
| --- | ---: | ---: |
| 종료 코드 | 0 | 0 |
| 출력 문자 수(stdout+stderr, 헤더 포함) | 1,913 | 2,023 |
| 전체 실행 시간 | 1.102초 | 1.048초 |

짧은 로그는 헤더 때문에 110자가 늘었다. 1회 시간 차이는 변동 범위이며 속도 개선 근거로 사용하지 않는다. 합성 반복 성공 로그 표본은 35,062자에서 요약 본문 108자로 줄었고 경고·Assertion 문구를 유지했다. 이 표본은 실제 개발 토큰 절감률을 나타내지 않는다.

루트 AGENTS.md는 2,908자 → 1,828자로 줄였다. 분리된 경로별 규칙과 요청 시 읽는 지도 비용은 별도다. 정확한 전후 토큰 계량, 캐시 효과, 재시도·작업 성공률의 장기 비교는 아직 하지 않았다.

초기 지침·ignore 사본과 원시 측정 JSON은 Git에서 제외된 `.codex-local/backups/`, `.codex-local/measurement.json`에 로컬로만 남긴다. 복원할 때 이후 변경을 덮어쓰지 않도록 diff로 비교한다. 제거하려면 기존 AGENTS/ignore와 비교해 추가 규칙을 되돌린 뒤 `tools/codex`와 관련 지도를 제거한다. 전역 설정·확장을 복원할 필요는 없다.


최종 검증은 18개 기준으로 WSL Python 3.12에서 17개 통과·Windows 전용 1개 제외, 실제 Windows Python 3.13에서 16개 통과·POSIX 전용 2개 제외였다. 새 지침·래퍼 명령이 CLI의 새 세션 prompt-input에 포함됨을 확인했고 `.codex-local/`의 Git 제외와 diff 형식 검사도 통과했다. CI에는 보조 도구 검사 명령을 추가했으며 원격 CI 결과는 별도다. 애플리케이션 런타임 코드는 변경하지 않아 전체 Role-AI 테스트·모델 추론·운영 재시작은 실행하지 않았다.

Windows 권한 검사 중 단순 상속 제거가 기존 명시적 권한을 남기는 것을 발견했다. Set-Acl 방식은 SeSecurityPrivilege 오류가 나 일반 사용자 실행에 적합하지 않았다. 최종 구현은 PowerShell 읽기 조회 + icacls DACL 수정으로 보완했고, 기존의 비어 있지 않은 미표시 폴더는 권한 변경 전에 거부하도록 검사했다. 이 문제의 회귀 검사도 포함했다.
