# 대화 요청 분석 미리보기

분석 전용 평가(PR #17)의 구조화 분석 스키마와 프롬프트를 대화 입력에도 사용합니다.
정답이 있는 평가 묶음을 채점하는 기능과, 실제 요청 하나를 분석하는 기능은 구분됩니다.
이 화면에는 정답이 없으므로 정확도나 신뢰도 점수를 표시하지 않습니다.

## 사용

1. 로컬 소유자로 로그인하고 메시지를 1~2000자로 입력합니다. 일반 채팅은 기존 4000자 제한입니다.
2. `요청 분석 · 로컬 Ollama`를 누르고 이번 요청의 로컬 전송을 확인합니다.
3. 목적, 의도, 작업 순서, 제약, 누락 입력, 확인 질문, 기대 출력을 확인합니다.
4. 추천 역할 버튼을 누르면 현재 역할 선택만 변경됩니다. 확인 질문에 맞게 입력을 보완하고 직접 전송합니다.

분석 입력이나 대화를 바꾸면 이전 미리보기는 폐기합니다. 분석 중 입력이 바뀌면 도착한 결과도 폐기합니다.
서버가 반환한 문자열은 HTML로 해석하지 않고 텍스트로 표시합니다.
분석 결과와 역할 추천은 DB에 저장하지 않습니다. Ollama 운영 환경의 로그 정책은 별도로 확인하세요.
이 변경은 DB 스키마를 변경하지 않으며 dev의 현재 버전은 v3입니다.

## 역할과 권한

| 감지 의도 | 추천 역할 |
| --- | --- |
| 테스트 작성 | 코드 테스트 |
| 코드 작성·수정 | Developer |
| 설명 | Professor |
| 나머지 | Assistant |

복수 의도에는 중복 없는 복수 후보를 보여주며 자동 선택하지 않습니다.
실행·학습·Worker 관리 의도를 감지해도 해당 기능을 호출하지 않습니다.
OpenClaw로 전환하거나 도구 차단 정책을 변경하지 않습니다.
역할 적용 후에도 원래 입력을 그대로 전송하며 분석 결과가 시스템 지시나 권한으로 주입되지 않습니다.
분석된 제약은 참고 결과이므로 빠뜨리거나 잘못 해석할 수 있습니다. 실제 권한 검사는 각 API에서 계속 수행합니다.

## API와 제한

`POST /api/request-analysis/preview`

```json
{"content":"이 코드의 테스트만 작성해 주세요. 실행은 하지 마세요.","approved":true}
```

로그인·CSRF·로컬 소유자 제한을 적용합니다. `approved`는 엄격한 boolean이고 매 요청 true가 필요합니다.
임의 provider, 실행 승인 등 추가 필드는 거부합니다. API는 작업을 등록하거나 실행하지 않습니다.
서버 설정의 Ollama만 사용하며 HTTP 루프백 또는 Compose의 host.docker.internal 주소만 허용합니다.
`/api/show`에서 completion 지원과 cloud 모델 메타데이터를 확인한 다음 한 번만 분석합니다.
공유 모델의 시스템 프롬프트로 동작하며 별도 모델을 다운로드하거나 설치하지 않습니다.
유료 API·Mock·대체 모델로 전환하지 않습니다. JSON 전체가 엄격한 Analysis 스키마에 맞아야 성공합니다.
모델이 보고한 cloud 메타데이터 확인은 네트워크 격리 자체를 제공하지 않습니다.

프로세스당 분석 1건, 전체 90초 제한입니다. 잘못된 출력은 수정·재시도 없이 실패합니다.
진행 중인 다른 분석은 409, 타임아웃은 504, 모델/스키마 실패는 502입니다.
내부 응답·예외 원문은 오류 메시지에 노출하지 않습니다.
기존 Ollama 생성 제한(num_predict 512, num_ctx 4096) 때문에 복잡한 분석은 JSON이 잘릴 수 있습니다.
그 경우 요청을 더 짧게 나눠야 합니다. 의미 정확도·실제 사용자 모델·브라우저 E2E는 별도 실환경 검증이 필요합니다.
